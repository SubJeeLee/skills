# COFA Delivery

실제 과제의 요구사항을 구현과 검증까지 연결한다. 사용자가 직접 목표·우선순위를 결정하고 코드와 결과를 이해할 수 있게 돕는다. 특정 스택이나 하네스를 기본값으로 강제하지 않는다.

## 먼저 확인할 경계

이 자료는 시험 허가를 제공하지 않는다. [응시 경계](references/exam-boundaries.md)를 처음 적용할 때 읽고, 최신 과제·운영 안내와 기존 프로젝트 지침을 우선한다. 시험 중 이 저장소 반입이 허용되는지 확인되지 않았다면 준비·리허설 자료로만 사용한다. AI 금지 서술형 단계라면 답안 작성·분석·검토를 수행하지 않는다.

## 유지할 기준

- 원문 요구와 해석·가정을 구분한다. 자료에 이미 답이 있는 질문은 반복하지 않는다.
- 결과를 바꾸는 업무 조건은 확인한다. 통상적인 구현 선택은 범위 안에서 진행한다.
- 완료 기준을 관찰 가능한 동작으로 정하고 구현 위치·검증 증거와 연결한다.
- 현재 환경을 먼저 실행한다. 가장 중요한 사용자 흐름을 끝까지 완성한 뒤 확장한다.
- 도구의 설치·인증·설정 비용을 실제 이점과 비교한다. 전체 프레임워크를 여러 개 겹쳐 실행하지 않는다.
- 에이전트의 완료 보고는 증거가 아니다. 관련 검사 결과와 실제 동작을 확인한다.
- 결정 이유, 실패와 수정, 남은 한계를 간결하게 남긴다. 기록이나 성공 수치를 꾸미지 않는다.

필요한 경우에만 [자산 템플릿](assets/)을 과제 작업 공간에 맞춰 사용한다. 기존 파일을 덮어쓰지 않으며, 과제에서 지정한 제출 파일이 우선이다.
