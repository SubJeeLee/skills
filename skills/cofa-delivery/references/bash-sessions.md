# 여러 Bash에서 Codex 역할 나누기

이 문서는 터미널 탭을 직접 여는 제공 환경에서 작업을 나누는 운영안이다. 여러 Bash 탭이 존재한다고 여러 Codex 세션·공유 파일·사용 한도까지 확인된 것은 아니다. 제공 실행 안내와 실제 파일을 확인하고 지원되는 범위에서 사용한다. 개인 로그인·별도 모델 연결·관리 설정 변경 없이 제공 Codex만 사용한다.

## 기본 시작은 메인이 준비

허용된 개발 과제에서 `cofa-delivery`를 호출하면 메인은 README·기존 지침을 읽은 뒤 다음을 진행한다. 다른 Skill이나 MCP는 필수가 아니다. 설치 자체로 실행되는 훅은 없다.

1. 기존 Spec Kit 명세·계획·작업 목록의 실제 위치를 확인한다. 없거나 도구가 제공되지 않으면 [계획 기준](planning-tools.md)에 따라 간결한 문서를 사용한다.
2. [초기화 도구](../scripts/bootstrap_parallel.py)를 **설치된 Skill의 실제 경로**로 호출한다. 예를 들어 `python3 <Skill 절대경로>/scripts/bootstrap_parallel.py --project-root <프로젝트 절대경로>`다. 기존 파일은 덮어쓰지 않으며, Python이 없으면 아래 최소 구조를 직접 만든다.
3. 생성된 배정표의 기준 문서 경로를 채우고, 독립 작업 하나의 요청을 작성한다. 기본 첫 요청은 `.cofa/tasks/R01.md`이며 기존 요청이 있으면 재개 상태를 확인하거나 새 ID·회차를 쓴다.
4. 실제 자료·유일한 담당·수정 범위·선행 계약·완료 조건·전용 보고서가 지정되면 요청의 배정 준비를 ready로 고정하고 배정표에도 ready로 등록한다. 이후 실행 상태의 유일한 기준은 배정표다. 미완성 양식을 작업 요청처럼 전달하지 않는다.
5. 사용자에게 Bash B를 열고 제공 Codex를 실행하도록 안내하면서, 그 세션에 읽힐 요청 경로와 시작 프롬프트를 제시한다. 메인은 충돌하지 않는 구현을 계속한다.

```text
.cofa/
├── coordination.md       메인이 관리하는 기준 경로·환경 확인·배정·접수
├── tasks/                메인이 완성한 회차별 작업 요청
├── reports/              보조가 작성하는 회차별 결과
├── snapshots/            필요할 때만 사용하는 고정 입력
├── templates/
│   ├── task.md           배정 전 채워야 하는 작업 양식
│   └── report.md         근거·변경·검사·한계 보고 양식
└── prompts/
    ├── main.md           메인 재개·시작 요청
    └── worker.md         첫 보조 세션에 전달할 요청
```

초기화 도구는 양식과 프롬프트만 만든다. 명세·구현 코드·ready 작업·성공 보고서나 세션은 생성하지 않는다. 첫 실제 작업과 기준 경로를 채우는 것은 **이 Skill을 수행하는 메인의 책임**이다. 재호출 시 기존 파일은 읽고 유지하며, 보조 프롬프트의 작업 경로와 담당 별칭은 해당 회차로 채운다. 양식만 존재하는 상태를 병렬 작업 준비 완료로 보고하지 않는다.

## 세 가지 방식을 구분

| 방식 | 시작과 결과 전달 | 기록할 표현 |
| --- | --- | --- |
| 별도 Bash의 독립 Codex 세션 | 사람이 각 세션을 시작하고 문서 경로·결과를 전달 | 수동 분리 CLI 세션. 이 문서의 주 운영안 |
| Codex 네이티브 서브에이전트 | 실제 지원될 때 메인이 위임 도구로 생성·취합 | 실제 도구와 세션이 확인된 서브에이전트 |
| 한 세션의 순차 역할 전환 | 같은 대화에서 검토 관점을 변경 | 순차 검토. 독립 세션 검증으로 표현하지 않음 |

별도 Bash 세션을 운영상 검토 담당·보조 에이전트라고 부를 수 있으나 네이티브 spawn이나 자동 오케스트레이션을 사용했다고 기록하지 않는다. 독립 대화여도 같은 모델의 판단 오류가 반복될 수 있으므로 원문과 증거를 확인한다.

## 최소 구성

| 탭 | 용도 | 쓰기 범위 |
| --- | --- | --- |
| Bash A | 메인 Codex: 문제 정의·질문 정리·구현·통합 | 기준 명세, 제품 코드·공유 설정과 작업 기록 |
| Bash B | 보조 Codex: 원문 검토, 독립 구현, 검증 또는 코드 추적 | 작업 요청에 배정한 파일과 전용 보고서만. 검토 작업이면 제품 코드 수정 금지 |
| Bash C(필요할 때) | 개발 서버·로그 또는 검사 명령 | 서버 프로세스나 지정 검사. AI 세션이라고 간주하지 않음 |

권장 시작은 메인 1개와 보조 1개이며 공식 제한은 아니다. 계약·파일 경계가 분리되고 자원과 시간이 충분할 때만 구현 보조를 추가한다. 보조 역할을 바꾸면 새 요청·읽을 입력·버전을 명시한다. 더 독립적인 재검토가 필요하면 지원되는 새 세션을 사용한다. 여러 모델이나 다른 인증은 필요하지 않다.

## 시작과 파일 공유 확인

1. Bash A에서 제공 작업 디렉터리와 README, 기존 지침, Codex 실행 방법을 확인한다.
2. 기준 명세와 실제 담당자 답변을 문서로 남기고 배정표에 경로를 연결한다. Spec Kit 문서의 내용을 다른 전체 명세로 복제하지 않는다. 개인 PC 파일이나 외부 메신저로 전달하지 않는다.
3. Bash B를 열고 같은 기준 문서를 실제로 읽을 수 있는지 확인한다. `pwd`가 같다는 사실만으로 같은 파일시스템이라고 단정하지 않는다. 기존 문서 경로·내용을 대조한다.
4. 제공 안내의 명령으로 별도 Codex를 실행한다. 일반 셸의 `codex` 실행은 예시이며 제공 런처가 있으면 그 방법을 따른다. 대화 식별자가 제공되면 메인과 다른 세션인지 확인하고, 같은 대화를 재개한 상태를 독립 검토라고 기록하지 않는다. 동시 실행이 막히면 별도 인증·연결 변경으로 우회하지 않는다.
5. 메인이 원문 경로, 기준 명세, 답변 기록, 입력 버전·수정 경계와 반환 위치를 요청 파일에 명시한다. 새 세션은 메인 대화를 자동으로 안다고 가정하지 않는다. 같은 프로젝트 지침을 자동으로 읽었는지도 확인한다. 확인한 사실만 배정표에 반영한다.

공유 파일에 접근할 수 없다면 제공 환경 안에서 허용된 텍스트 전달 방법을 사용한다. 그마저 불가능하면 메인 세션의 순차 검토로 전환하고 검증 방식을 정확히 기록한다.

## 작업 분해와 입력 안정화

[작업 요청 양식](../assets/parallel/task.md)에 기준 작업 ID, 관련 파일과 요구사항·회차를 연결한다. 경로명은 예시이며 기존 과제 문서와 필수 제출 파일을 우선한다. 이전 [검토 전용 양식](../assets/review-request.md)은 읽기 전용 검토에만 사용할 수 있다.

| 시점 | 메인 | 독립적으로 맡길 작업 |
| --- | --- | --- |
| 문제 정의 | 담당자 질문·첫 실행 범위 | 원문 대비 누락·근거 없는 가정 검토 |
| 인터페이스 확정 | 핵심 사용자 흐름 연결 | 입출력·오류 처리 계약이 고정된 함수·모듈 구현 |
| 첫 흐름 실행 후 | 다음 필수 기능 | 이미 완성한 흐름의 검증 또는 실제 호출·데이터 추적 |
| 제출 전 | 최종 통합·검사·제출 | 새 구현 배정을 멈추고 최종 상태·설명 대조 |

같은 파일에는 한 명의 수정 책임자만 둔다. 기준 명세·계획·작업 목록, 패키지·잠금 파일, 공통 타입·공유 설정은 메인이 관리한다. 디렉터리 배정은 재귀 범위와 제외 파일을 명시하고 다른 배정과 겹치지 않게 한다. 범위 밖 변경은 제안만 반환한다. 여러 Bash를 열었다는 이유로 파일이 격리되거나 잠겼다고 보지 않는다.

검토할 명세·코드는 해당 범위의 수정을 잠시 멈추거나 관련 입력의 고정 스냅샷·내용 해시를 사용한다. 커밋 SHA만으로 미커밋 파일까지 고정됐다고 보지 않는다. 입력이 바뀌면 영향받은 판단을 재검토한다. 계약이 변경되면 관련 작업자를 먼저 중지·확인한 뒤 새 회차로 배정한다. 공유 DB·서버 상태를 바꾸는 검사도 순서를 조율한다.

## 각 Bash에 전달할 요청

기본 요청은 초기화가 만든 `.cofa/prompts/main.md`와 `.cofa/prompts/worker.md`다. 설치된 Skill과 프로젝트의 실제 경로가 들어간다. 메인은 요청을 완성하고 배정표의 ready 상태·유일한 담당을 지정한 뒤 보조 프롬프트의 작업 경로와 담당 별칭을 채운다. 그 뒤 사용자가 해당 Bash를 그 담당으로 지정하고 아래처럼 읽힐 수 있다. 재배정 시에는 실제 작업 경로와 담당으로 바꾼다.

```text
.cofa/prompts/worker.md를 읽고 배정된 작업만 수행해줘.
```

보조 세션은 `worker` 역할을 먼저 확인하고 **메인 초기화와 추가 작업자 배정을 하지 않는다.** 요청·기준 입력·수정 범위가 비어 있으면 빈 양식으로 작업하지 않는다. 원문 검토는 필요한 Skill이 함께 제공됐을 때만 그 Skill을 읽으며, 폴더가 없어도 요청과 원문 근거만으로 진행할 수 있다.

보조는 요청의 배정 준비와 배정표의 실제 실행 상태·담당을 대조한다. 첫 시작은 ready 상태의 유일한 지정 담당만 수행하고, 메인은 시작 확인 후 running으로 기록한다. running 작업은 실제 세션 정보 또는 사용자 확인으로 같은 담당임을 확인한 경우에만 재개한다. 같은 별칭을 복사했다고 기존 세션이 되지는 않는다. 소유권이 불명확하면 제품 수정 전에 확인한다. completed 보고서가 있거나 reported·accepted·cancelled인 회차는 재실행하지 않고 메인에게 다음 배정을 요청한다. 이는 운영 절차이며 기술적 잠금·인증은 아니다.

## 회수와 종료

보조는 [보고 양식](../assets/parallel/report.md)에 따라 회차 전용 결과를 완성하고 작업 ID·회차·경로·상태를 응답한다. 요청·공유 배정표는 메인만 수정하고, 각 보조는 다른 보고서 파일을 쓴다. 작성 중 파일과 이전 회차 결과를 새 완료 결과로 접수하지 않는다.

파일 저장은 다른 세션에 알림을 보내지 않는다. 사용자가 메인에 보고서 경로를 알려주는 방식을 기본으로 한다. 메인이 확인하기로 했다면 독립 작업의 구간 끝에서 해당 경로만 확인하고, 무한 감시 루프·짧은 주기의 모델 호출을 만들지 않는다. 메인은 기준 입력·원문·현재 diff·검사 근거를 확인하고 통합 후 관련 검사를 수행한 뒤 accepted로 기록한다. 공유 폴더의 수정은 이미 현재 코드에 보이므로 별도 브랜치처럼 중복 적용하지 않는다.

첫 검토는 5~10분을 권장 시작점으로 하며 중요한 충돌만 먼저 회수한다. 이는 공식 시간 제한이 아니다. 문서의 완벽함을 목표로 질문과 검토를 무한 반복하지 않는다. 보고서가 완료돼도 코드·검사 근거가 부족하면 보완·보류하고 성공을 만들어 기록하지 않는다.

지원 환경에서 실제로 진행 중인 세션과 서버를 확인하고, 중단·역할 교체는 사람이 해당 탭에서 수행하거나 제공된 제어 기능을 사용한다. 중단을 확인하기 전 동일 파일의 새 수정자를 투입하지 않는다. 보조 세션이 끝나도 개발 서버가 필요하면 별도로 유지한다.

이 운영안은 세션 생성·메시지 자동 중계·파일 잠금을 구현하지 않는다. MCP 설정과 독립 세션 실행 지원도 별개다. 실제 시험의 동시 실행 허용·자원·토큰 범위는 제공 환경에서 확인한다.

MCP는 별도 CLI 설정 변경보다 [COFA MCP 탭의 JSON 안내](mcp-json.md)를 따른다. 저장 이후 메인·검토 세션마다 도구 검색과 필요한 호출을 확인한다.
