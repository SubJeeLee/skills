# 단계별 요청 예시

아래는 미래 작업을 위한 예시다. 읽는 즉시 실행할 명령이 아니다. 과제와 기존 지침에 맞춰 바꾸며, 도구가 없으면 사용했다고 주장하지 않는다. 시험에 개인 자료를 반입할 수 있는지는 먼저 확인한다.

## 시작

```text
너는 업무 요구를 실행 가능한 소프트웨어로 구체화하는 개발 파트너다.
나는 목표·우선순위를 결정하고 결과를 직접 확인한다.
README, 과제 안내, 기존 지침과 코드를 먼저 읽어줘.
사용자와 문제, 필수 요구사항·제출물, 기존 구현, 실행·검사 방법,
중요한 미확인 조건, 첫 핵심 사용자 흐름을 짧게 정리해줘.
명시된 사실과 추정을 구분하고 환경·업무 규칙을 임의로 만들지 마.
```

## 질문 선별

```text
미확인 조건 중 결과를 바꾸는 질문만 골라줘.
질문마다 답에 따라 어떤 설계가 달라지는지 붙여줘.
자료에 답이 있는 질문은 제외하고, 일상적인 구현 선택은 스스로 진행해줘.
```

## 명세와 설계

```text
확인한 요구사항으로 기준 명세와 기술 계획을 작성해줘.
요구사항 ID·근거·우선순위·관찰 가능한 완료 기준·검증 방법을 연결하고,
데이터 흐름, 상태 규칙, 중요한 가정과 구현 순서를 정리해줘.
제공된 구조를 우선 활용하고 첫 핵심 흐름을 끝까지 완성하는 계획을 세워줘.
```

## 명세 검토

```text
너는 명세의 검토자다. 과제와 실무자 답변을 기준으로
누락·모순·불명확한 가정을 찾아줘.
새 명세를 따로 만들지 말고 문제·근거·영향·수정 제안을 제시해줘.
구현 전 확인, 가정 명시 후 진행 가능, 범위 밖을 구분해줘.
```

## 구현

```text
합의한 첫 사용자 흐름을 입력부터 결과 재조회까지 구현해줘.
기존 구조와 허용된 도구를 활용하고 무관한 기능·리팩터링은 추가하지 마.
변경한 동작에 맞는 검사를 실행하고 변경 파일, 실제 결과,
미검증 항목과 남은 한계를 보고해줘.
```

## 디버깅

```text
현재 관찰한 실패와 재현 조건을 먼저 확인해줘.
입력·처리·저장·출력 경로를 추적해 원인 가설을 제시하고,
최소 변경으로 수정한 뒤 같은 재현 조건과 관련 회귀를 다시 검증해줘.
플랫폼 설정이나 연결 프로세스는 변경하지 마.
```

## 읽기 전용 검토

```text
요구사항과 현재 변경을 비교해 읽기 전용으로 검토해줘.
누락, 잘못된 입력, 실패 처리와 실제 과제에 관련된 권한·상태 규칙을 확인해줘.
각 발견에 재현 조건과 파일 위치를 붙이고,
코드만 읽은 판단과 실제 실행한 결과를 구분해줘.
```

## 인계

```text
현재 목표, 완료 사항과 증거, 중요한 파일·결정,
실패 재현법, 실행 명령·포트, 미검증 범위와 다음 작업을
기존 작업 기록에 간결하게 정리해줘.
다음 세션이 같은 탐색을 반복하지 않을 만큼만 남겨줘.
```

## 제출 전 이해도 점검

```text
구현과 작업 기록에 근거해 핵심 데이터 흐름, 설계 이유와 대안,
실제 오류·재검증, 미구현 사항, 중요한 위험을 설명해줘.
코드와 연결되는 위치를 짚어줘. 검증하지 않은 사실을 만들지 마.
그 후 나는 AI 없이 직접 설명해보겠다.
```

마지막 요청은 AI가 허용된 단계에서만 사용한다. 후속 서술형이 시작된 뒤에는 사용하지 않는다.
