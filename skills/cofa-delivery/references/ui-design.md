# UI 구현과 후순위 디자인

문제 정의 → 요구사항 확정 → 기술 설계 → 필수 기능 구현 → 주요 검증·오류 수정 → 선택 디자인 개선 순서를 유지한다. 웹 UI가 없는 작업에는 이 자료를 적용하지 않는다. 기획을 다듬기 위해 디자인 Skill을 먼저 실행하거나 별도 디자인 시간을 확보하지 않는다.

## 첫 UI 구현: frontend-design의 기본 원칙만

기획·요구·기술 계약이 정해지고 UI 작업이 배정되면 [frontend-design 원문](ui/frontend-design.md)을 이 범위 안에서 읽는다. 원문의 별도 디자인 계획·대안 비교·독창성 확인 절차를 다시 수행하지 않는다.

- 기존 컴포넌트와 제품 스타일을 재사용한다. 색상·글자 크기·간격·정보 위계의 최소 기준만 기존 명세나 공통 토큰 위치에 짧게 연결하고 바로 기능을 구현한다.
- 과제의 실제 데이터와 사용자 행동을 화면에 반영한다. 획일적인 카드·장식·큰 홍보 문구를 자동으로 붙이지 않되, 익숙한 UI 패턴이나 지정 색상·폰트를 새로움만을 위해 바꾸지 않는다.
- 기존에 사용 가능한 한글 글꼴과 자산을 우선한다. 원격 폰트·이미지 수집, 새 UI·모션 라이브러리 설치와 샘플 화면 여러 개 제작을 첫 구현의 선행 조건으로 만들지 않는다.
- 라벨, 읽기 순서, 키보드 초점, 유효성 검사, 로딩·오류·빈 결과와 반응형의 사용 가능성은 기능 품질이다. 이를 장식으로 분류해 뒤로 미루지 않는다.
- UI 정보가 일부 비어 있으면 기존 스타일과 요구사항의 성공 장면을 기준으로 보수적으로 구현한다. 이미 확정한 기획을 다시 질문하거나 별도 브랜드 워크숍을 시작하지 않는다.

구현 규모는 [Ponytail full](ponytail.md) 기준으로 제한한다. 이 단계에서는 보이는 화면의 사용 가능성이 목표이며 장식적 디자인과 애니메이션은 보류한다.

## 선택 개선: Emil은 기능과 주요 검증 이후

아래 조건을 메인이 실제 기준 작업 목록과 검사 결과로 확인한 경우에만 적용한다.

1. 필수 사용자 흐름과 요구 기능이 구현됐다.
2. 과제에 맞춰 정한 주요 인수 검사가 완료됐고, 해결되지 않은 기능 오류보다 디자인을 먼저 처리하지 않는다.
3. 검증·문서·제출에 필요한 시간을 남기고도 여유가 있으며 메인이 대상과 수정 파일을 배정했다.

조건을 충족하지 않으면 Emil 원문·레시피를 추가로 읽거나 감사 계획을 만들지 않고 기존 구현·검증을 계속한다. 조건을 충족하면 [emil-design-eng 원문](ui/emil-design-eng.md)에서 해당 화면의 세부 원칙만 적용한다. 특정 상호작용의 모션이 필요한 경우에만 [animate 원문](ui/animate.md)과 그 원문이 요구하는 [RECIPES](ui/RECIPES.md)를 추가로 읽는다. 기본은 기존 CSS·컴포넌트·설치된 도구를 사용하는 작은 수정이다.

- 사용자에게 결과·상태 변화를 알려주는 반응을 우선하고, 반복되는 등장 효과·배경 루프·대형 히어로 모션은 추가하지 않는다.
- 원문의 준비 완료 인사, 전체 화면 재설계, 전체 저장소 감사, 새 계획 문서와 추가 에이전트 생성으로 현재 작업을 멈추거나 확장하지 않는다.
- 설치된 라이브러리 버전과 실제 지원을 확인한다. 원문의 예제나 성능 설명을 현재 환경에서 검증한 사실로 취급하지 않는다.
- 필요한 모션 감소 설정·중단 가능성과 초점·읽기 순서를 유지한다. 요구사항에 명시된 필수 상호작용과 접근성 수정은 원래 기능 작업으로 처리한다.
- 시간이 부족하거나 기능·검사가 바뀌어 조건이 깨지면 선택 개선을 중단하고 다시 구현·검증을 우선한다.

## 병렬 세션과 확인

메인이 공통 스타일·토큰의 수정 책임을 관리한다. 보조는 배정된 UI 파일만 수정하고, 공통 컴포넌트 변경이 필요하면 메인에게 근거를 반환한다. `polish`라는 역할 이름이 새로운 권한이나 완료 증거가 되지는 않는다.

브라우저 자동화·캡처·외부 자산 검색은 환경과 시험 지침이 허용하는 경우에만 한다. 정적 코드 확인, 직접 관찰, 실행한 검사를 구분하고 실제로 보지 않은 화면을 시각 검증 완료로 기록하지 않는다. 원문을 읽는 것만으로 외부 도구·MCP·모델·플러그인을 설치하지 않는다.

재개 시에는 기존 요청과 파일 소유권을 확인하고, 진행 중 작업을 새 디자인 작업으로 바꾸지 않는다. 이전에 생성한 프롬프트는 초기화가 덮어쓰지 않으므로 메인이 필요한 경로와 적용 시점을 반영한다.
