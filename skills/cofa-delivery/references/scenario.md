# 180분 구현과 후속 설명 연습 시나리오

아래 시간은 추천 배분이며 공식 배점·필수 절차가 아니다. 과제가 이미 명확하면 분석을 줄이고, 중요한 업무 조건이 불명확하면 질문을 우선한다. 180분 전체에는 검증·문서·제출도 포함된다.

## 역할

- 사람: 목표와 범위 확정, 업무상 선택, 실제 동작 검토, 결과 이해.
- 메인 코딩 에이전트: 원문·코드 확인, 설계, 구현, 명령 기반 검증과 수정.
- 검토 역할: 과제와 명세·구현의 누락·모순을 근거로 지적. 별도 에이전트가 없으면 순차 검토하며 독립 검토라고 주장하지 않는다.
- 실무자 에이전트: 과제에 남은 업무 조건 확인. 과제 원문과 답변이 충돌하면 차이를 확인한다.

병렬 작업이 유리하고 제공 환경이 지원하면 [멀티 에이전트 운영](multi-agent.md)에 따라 탐색·검증을 분리한다. 역할과 동시 실행 수는 작업에 맞춰 줄이며, 하네스 설치 자체를 시간표의 목표로 두지 않는다.

## 시간별 진행

| 경과 | 할 일 | 다음 단계로 갈 기준 |
| --- | --- | --- |
| 0~10분 | 안내된 본인 확인, README·기존 지침·환경·제출물 확인 | 필수 조건과 실행 경로 파악 |
| 10~20분 | 영향이 큰 미확인 조건 질문, 우선순위 확인 | 사실과 가정, 핵심 사용자 흐름 구분 |
| 20~30분 | 기준 명세·설계 정리, 필요한 누락 검토 | 완료 기준과 데이터 흐름, 첫 검증 방법 확보 |
| 30~80분 | 핵심 흐름 구현 | 입력부터 결과 재조회까지 한 번 실행 |
| 80~125분 | 나머지 필수 기능, 오류·경계 처리 | 필수 조건별 구현 상태 확인 |
| 125~150분 | 관련 검사와 직접 동작 확인·수정 | 증거와 미검증 범위 확보 |
| 150~170분 | 최종 검증, 실행 문서, 결정·한계 이해 | 사람이 핵심 구조를 설명 가능 |
| 170~180분 | 제출 미리보기·저장·필수 경로 확인과 확정 | 후속 단계로 정상 진행 |

전체 마감은 별도다. 제출 확정 후에는 수정할 수 없다. 후속 질문 준비 지연까지 고려하며 14:00 종료를 넘기지 않는다.

## 가상 연습 과제

메신저로 받는 설비 이상 신고의 담당자·상태를 추적하기 어렵다. 등록·조회·담당자 지정·상태 변경 도구를 만든다. 실제 비공개 과제나 출제 예측이 아니다.

1. 등록 사용자와 처리 담당자를 구분한다.
2. 누락 방지·상태 확인·처리 지연 중 어떤 문제가 우선인지 확인한다.
3. 담당자 지정 방식, 허용 상태 전이, 완료 필수 정보를 질문한다.
4. 정상 등록·재조회, 누락 입력 거부, 정상·비정상 상태 변경을 완료 기준으로 정한다.
5. 기존 환경에서 핵심 흐름을 먼저 연결한다. 인증·통계·AI 기능을 임의로 추가하지 않는다.
6. 실패를 발견하면 실제 재현·수정·재검증만 기록한다.
7. 연습 종료 후 AI 없이 여섯 질문에 각각 5분 동안 답한다.

## 사전체험 15분 배분

- 0~3분: 실제 장비에서 감독 연결.
- 3~6분: README, 파일 생성·저장, 터미널.
- 6~9분: 제공 Codex 응답과 승인 대기 처리.
- 9~12분: 서버 실행, 포트·경로와 Browser 미리보기.
- 12~15분: Cofa Helper, 종료와 후속 문항 흐름.

체험은 1회이므로 장비 준비를 마친 뒤 사용한다. 시험 단계에서 개인 자료를 읽을 권한을 추정하지 않는다.
