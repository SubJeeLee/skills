# AI 없이 답하는 서술형 연습

이 문서는 시험 전 리허설 또는 AI가 허용된 구현 단계의 이해도 점검용이다. 실제 AI 금지 후속 서술형에서 읽히거나 답안 생성·검토를 요청하는 용도로 사용하지 않는다. 제출 후 docs 열람 허용 여부도 확인되지 않았다.

## 준비 방법

중요한 변경마다 입력·검증·처리·저장·출력 경로를 사람이 직접 설명해본다. 설계의 이유, 대안, 실제 오류와 수정, 확인한 범위, 남은 위험을 기록한다. 구현하지 않은 내용을 구현했다고 말하지 않는다.

## 6개 연습 주제

1. 핵심 문제를 무엇으로 정의했고 왜 그 기능을 우선했는가?
2. 중요한 입력은 어떤 파일·함수를 거쳐 결과가 되는가?
3. 왜 이 구조를 선택했고 어떤 대안을 포기했는가?
4. AI의 결과에서 어떤 오류를 발견하고 어떻게 재검증했는가?
5. 현재 가장 중요한 실패 가능성과 다음 검증은 무엇인가?
6. AI가 한 작업과 사람이 판단·확인한 부분은 무엇인가?

실제 출제 문항이나 공식 배점이 아니다. 도구 이름을 답변의 중심에 두지 않고 실제 구현과 판단을 설명한다.

## 답변 구조

질문에 대한 결론 → 구체적인 구현·행동 → 선택 이유 → 실제 증거 → 한계·다음 확인.

예: '저장 성공 표시만으로 완료라 보지 않고 재조회 결과를 확인했다. 화면 상태는 바뀌었지만 서버 저장이 실패하는 경우를 구분하기 위해서다.' 실제 확인한 경우에만 쓸 수 있다.

질문의 전제가 실제 코드와 다르면 차이를 밝힌 뒤 자신의 구현을 설명한다. API 이름·테스트 명령·통과 숫자를 기억하지 못하면 추측하지 말고 정확히 설명 가능한 행동과 결과를 쓴다. 답변을 좋게 보이게 하려고 오류·대안·성과를 꾸미지 않는다.

## 5분 연습 배분

- 0~45초: 무엇을 묻는지 파악, 결론과 실제 사례 선택.
- 45초~3분 45초: 구현·이유·증거·한계를 직접 작성.
- 나머지: 질문에 답했는지, 사실과 추정을 섞지 않았는지 검토.

공식 시간 배분이 아닌 연습안이다. 모의 프로젝트 종료 후 AI를 닫고 여섯 질문에 각각 직접 답해본다. 문서 없이 설명이 막히는 지점을 학습 대상으로 삼는다.
