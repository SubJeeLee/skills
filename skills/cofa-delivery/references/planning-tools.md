# Spec Kit 중심의 명세와 작업 분해

Spec Kit을 기본 계획 도구로 사용한다. 실제 설치본의 Codex 통합과 명령을 확인한 뒤 사용하며, 이 Skill은 Spec Kit을 설치하거나 설정을 변경하지 않는다. 사용할 수 없다면 기존 프로젝트 문서에 같은 항목을 간결하게 정리하고 구현을 시작한다.

## 하나의 기준 문서 유지

1. README·제공 데이터·기존 코드와 실제 담당자 답변을 읽는다.
2. 기존 Spec Kit 명세가 있으면 요구사항·가정·인수 조건을 갱신한다. 없으면 실제 설치본의 절차에 맞춰 필요한 문서만 작성한다.
3. 기술 계획에 데이터 흐름, 공통 인터페이스, 오류 처리와 첫 실행 방법을 남긴다. 첫 사용자 흐름을 끝까지 구현할 수 있으면 초기 설계를 종료한다.
4. 작업 목록에 선행 조건·담당 파일·완료 검사를 연결한다. 독립적인 작업만 병렬화하고, 이름만 FE·BE로 나눠 독립이라고 보지 않는다.
5. `.cofa/coordination.md`에는 이 명세·계획·작업 목록의 실제 경로와 배정만 기록한다. `.cofa/tasks/`의 요청은 해당 작업을 위임하는 계약이며 새 전체 명세가 아니다.
6. 검토 결과와 구현 중 변경 사항은 메인이 같은 기준 문서에 반영한다. 다른 세션이 명세나 공통 계약을 동시에 수정하지 않는다.

문서의 개수나 전체 프레임워크 절차의 완료가 목표는 아니다. 180분 과제라면 초기 분석·계획은 20~30분을 권장 목표로 하며 중요한 미확인 조건과 독립 작업을 분리해 진행한다. 필수 조건을 시간만으로 삭제하지 않는다.

## 검토의 위치

원문과 명세의 누락·모순은 보조 Codex에 범위를 정해 검토시킨다. 제공돼 있으면 `cofa-requirements-review`를 읽히고, 없으면 [Bash 세션 운영](bash-sessions.md)의 요청·보고 양식으로 수행한다. 추가 계획 하네스는 요구하지 않는다.

출력은 문제 / 원문 근거 / 구현 영향 / 최소 조치 / 중요도로 제한한다. 미확인 조건은 구현 전 확인, 가정 명시 후 진행 가능, 범위 밖으로 나눈다. 구현 후 디버깅·검증 Skill이 이미 제공돼 있고 실제 필요할 때만 해당 부분을 활용하며 계획 문서를 다시 생성하지 않는다.
