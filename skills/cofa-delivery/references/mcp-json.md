# COFA MCP 탭의 JSON 연결

참가자가 제공한 사전체험 화면에는 MCP 탭에 `{"mcpServers": {}}`와 저장 버튼이 표시돼 있다. 공식 상세 가이드도 해당 탭의 서버 JSON을 저장하면 제공 Codex 설정에 반영된다고 안내한다. COFA에서는 이 화면을 설정 진입점으로 사용한다.

일반 Codex 문서의 `~/.codex/config.toml`, `[mcp_servers...]`, `codex mcp add`와 다른 클라이언트의 `servers`, `mcp.servers` 예시를 그대로 붙여 넣지 않는다. 기존 관리 파일을 직접 수정하거나 여러 설정 경로에 중복 등록하지 않는다.

화면으로 확인된 것은 최상위 `mcpServers`와 JSON 저장 방식이다. 각 서버의 `url`, `command`, `args`, `headers`, `env`, 선택적인 전송 방식 필드를 COFA가 어떻게 수용하는지는 예제 저장·도구 검색·호출로 확인해야 한다. 아래 파일들은 공식 서버 설정을 해당 JSON 형태로 정리한 예시이며 COFA에서 연결 성공을 실측한 구성은 아니다.

브라우저 자동 조작 계열은 MCP 사용 가능 여부와 별개로 허용 확인이 필요하므로 자동 추가 예제로 묶지 않는다. 필요한 서버 하나씩 연결하고 실제 이점이 없는 항목은 추가하지 않는다.

## 기본 형태와 필드

```json
{
  "mcpServers": {
    "openaiDeveloperDocs": {
      "url": "https://developers.openai.com/mcp"
    }
  }
}
```

이 예시는 원격 HTTP 서버다. OpenAI Docs는 문서 조회용이며 개인 OpenAI 모델 API를 호출하는 도구가 아니다. COFA가 `url`이나 해당 전송 방식을 지원하지 않으면 지원된다고 가정해 필드를 임의로 바꾸지 말고 도움말을 확인한다.

로컬 프로세스 서버 예제의 `command`는 실행 파일 하나, `args`는 인자별 문자열 배열이다. 셸 명령 전체를 `command`에 넣거나 인자를 하나의 문자열로 합치지 않는다. `env`는 클라이언트가 지원할 때 서버에 전달하는 문자열 환경변수 맵이며, 실제로 필요한 경우에만 사용한다. JSON 문자열 안의 `$(pwd)`, `$HOME`, `~`나 다른 도구의 변수 문법이 자동 확장된다고 가정하지 않는다.

`npx` 기반 설정은 서버 시작 시 패키지를 내려받아 실행할 수 있다. JSON을 저장하는 것이 단순 메모에 그친다고 보지 말고 실행될 패키지·의존성·외부 연결을 확인한다. Serena 예제는 이미 설치된 `serena` 실행 파일을 전제로 하며 설치나 `serena setup`·훅 등록을 자동 수행하지 않는다.

## 적용 순서

1. 현재 MCP JSON을 확인한다. 기존 항목이 있으면 제공 작업 공간에서만 복구 가능한 형태로 보존하고 인증값을 대화·보고서·공개 저장소에 출력하지 않는다.
2. 서버 하나를 선택하고 공식 문서의 실행 방식과 환경 의존성을 확인한다. 예제의 `REPLACE_WITH_ALLOWED_CONTEXT7_API_KEY`와 `/ABSOLUTE/PATH/TO/PROJECT`는 실제 허용 값으로 바꿔야 한다. 대체 전 그대로 저장하지 않는다.
3. 선택한 서버 객체만 기존 `mcpServers` 내부에 합친다. 최상위 객체나 서버 이름을 중복 작성하지 않고 다른 서버의 값을 덮어쓰지 않는다. JSON 주석·후행 쉼표를 넣지 않는다.
4. COFA MCP 탭에 JSON을 입력하고 저장 결과·오류를 확인한다. 이 공개 저장소의 JSON 파일을 내려받았다는 사실만으로 연결됐다고 보지 않는다.
5. 현재 Codex 세션에서 MCP 서버와 실제 도구 목록이 보이는지 확인한다. 해당 설치본이 `/mcp`를 제공하면 사용할 수 있고, 없으면 제공 UI·에이전트의 도구 목록을 따른다. 저장 직후 기존 세션이 자동 갱신된다고 가정하지 않는다.
6. 필요하다면 작업을 저장한 뒤 제공 안내에 맞춰 관련 Codex 세션만 새로 시작한다. 플랫폼 전체 새로고침이나 개발 서버 종료를 기본 절차로 삼지 않는다.
7. 공개 일반 문서 질의 또는 합성 프로젝트의 읽기 작업 한 건으로 호출을 확인한다. 실제 문제·코드·데이터를 외부 문서 MCP의 검색어에 넣지 않는다.

등록·도구 검색·실제 호출을 별도 상태로 기록한다. JSON 구문 검사는 연결·인증·사용 허가 검증이 아니다. 실패하면 기존 설정으로 해당 변경만 되돌리고 기본 도구로 진행할 수 있다.

## 서버별 첫 확인

- OpenAI Docs: 일반적인 OpenAI 기능의 공식 문서 하나를 검색하고 출처를 반환하도록 한다. 시험 자료를 첨부하지 않는다.
- Context7: 실제 사용할 라이브러리명·버전의 일반 사용법만 조회한다. 인증이 필요하면 제공되거나 명시적으로 허용된 방식만 사용한다. 개인 AI API 키 금지와 문서 서비스 인증을 임의로 동일시하거나 별개이니 허용됐다고 단정하지 않는다. 외부 로그인 우회를 만들지 않는다.
- Serena: 실제 활성 프로젝트 경로를 확인한 뒤 합성 프로젝트 또는 허용된 코드의 함수 정의·참조를 읽는다. 수정 도구도 제공할 수 있으므로 검토 담당의 사용 범위는 읽기 중심으로 지정하고, 역할 지시가 기술적인 권한 제한을 만든다고 가정하지 않는다.

Context7 API 키를 예제 인자로 표현한 것은 공식 연결 형태를 보여주기 위한 것이다. 실제 인증값은 공개 파일·공유 명령 기록에 남기지 말고 COFA가 제공하는 허용된 비밀값 전달 방식이 있으면 그것을 따른다. 그런 방식과 사용 권한이 확인되지 않으면 이 서버는 보류한다.

## 여러 Bash 세션에서의 확인

MCP 탭 저장과 Bash A·B 각각의 도구 로딩은 구분한다. 두 Codex 세션에서 필요한 도구가 실제로 보이는지 따로 확인한다. 한쪽에서 성공했다고 다른 쪽도 연결됐다고 기록하지 않는다. 각 클라이언트가 로컬 서버를 별도 시작하면 프로세스·메모리·인덱싱 비용이 중복될 수 있으므로 필요한 세션에서만 사용한다.

검토 담당에게 MCP가 필수는 아니다. 원문과 파일 대조가 기본 셸 도구로 가능하면 그것으로 진행한다. MCP 연결 성공이 자동 세션 간 통신이나 서브에이전트 생성을 뜻하지 않는다.

## 오류를 구분하기

| 관찰 | 확인할 내용 |
| --- | --- |
| JSON 저장 실패 | 중괄호·쉼표·큰따옴표, 중복 키와 최상위 `mcpServers` |
| 알 수 없는 필드·전송 방식 | COFA가 지원하는 서버 필드. TOML·다른 클라이언트 예시와 혼용했는지 |
| 실행 파일 없음 | 제공 환경의 `command` 경로·PATH와 실제 설치 여부. 개인 PC 설치 여부와 구분 |
| 서버 시작·도구 검색 실패 | 런타임·패키지·언어 서버·프로젝트 경로·인증·연결 오류를 비밀값 없이 확인 |
| 도구는 보이지만 호출 실패 | 실제 질의·활성 프로젝트·인증 범위와 서버 응답 |
| 저장 후 기존 세션에 반영되지 않음 | 새 세션 로딩 필요 여부를 제공 안내에서 확인 |

오류가 반복되면 시각, 서버명, 단계와 인증값을 가린 오류를 남겨 제공 도움말을 확인한다. 프록시·터널·별도 인증 또는 관리 설정 변경으로 차단을 우회하지 않는다.

## 설정 준비 요청 예시

```text
cofa-delivery의 MCP JSON 연결 안내를 읽어줘.
현재 MCP 탭은 mcpServers 객체를 사용하는 JSON 방식이야.
필요한 서버 한 개의 설정만 기존 항목을 보존해 합칠 수 있도록 작성해줘.
TOML이나 codex mcp add 명령을 설정 화면에 붙여 넣으라고 하지 마.
서버의 의존성, 바꿔야 할 예제 값, COFA에서 아직 확인할 필드를 구분해줘.
인증값을 요구하거나 출력하지 말고 허용된 전달 방식이 없으면 보류해줘.
저장 이후 각 Codex 세션에서 도구 목록과 일반 질의 한 건을 확인할 방법을 알려줘.
연결을 실제 확인하기 전에는 성공했다고 기록하지 마.
```
