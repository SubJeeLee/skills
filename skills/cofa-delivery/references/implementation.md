# 구현과 위임

## 첫 단계

기존 프로젝트를 실행하고 검사 명령의 유효성을 확인한다. 패키지 관리 도구와 잠금 파일을 유지한다. 없는 테스트·서비스·외부 API를 있다고 가정하지 않는다. 새 의존성은 실제 기능과 설치 비용을 비교한다.

## 핵심 흐름 우선

입력부터 저장·출력·재조회까지 연결되는 작은 기능 단위로 진행한다. 화면만 만들거나 백엔드만 완성한 상태로 전체 요구사항을 충족했다고 하지 않는다. 기존 동작과 과제의 필수 조건을 우선하며 무관한 리팩터링을 덧붙이지 않는다.

## 위임 계약

작업마다 목표, 관련 파일·인터페이스, 완료 기준, 제약, 확인할 증거를 전달한다. 결과에는 변경 파일, 실제 검증, 미검증 항목과 남은 한계를 요구한다. 긴 원문·로그 전체를 매번 다시 전달하지 않는다.

## 병렬 작업

- 실제 제공된 서브에이전트·세션 기능과 권한을 확인한 뒤 사용한다.
- 독립 조사나 읽기 전용 검토부터 분리한다. 같은 파일에 동시 쓰기를 피한다.
- 인터페이스가 확정된 독립 구현만 경계를 명시해 병렬화한다.
- 단순한 역할 전환을 다른 독립 에이전트의 검토로 표현하지 않는다.
- 응답 지연, 토큰·CPU·RAM과 통합 비용을 고려한다. 병렬 수를 늘리는 것을 목표로 삼지 않는다.

## COFA 서비스 실행

웹 서비스라면 안내된 Browser에서 실제 포트와 경로를 지정한다. 서버는 안내에 맞춰 `0.0.0.0`에 바인딩하고 서버 터미널을 유지한다. 연결 실패 시 서버 로그·종료 여부 → 포트 → 바인딩 → 경로 순서로 확인한다. 터널이나 외부 배포로 제한을 우회하지 않는다.

자동 저장과 AI의 디스크 변경이 충돌하면 양쪽 내용을 비교하고 보존할 내용을 선택한다. 파일을 만들었다는 보고와 실제 저장 완료를 구분한다.
