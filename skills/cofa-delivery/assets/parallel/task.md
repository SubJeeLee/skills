# 작업 요청

- 작업 ID·회차: 메인이 지정
- 역할: worker
- 배정 준비: draft
- 유일한 담당 세션 별칭: 메인이 지정
- 목적과 기준 작업 ID: 메인이 지정
- 요청 작성자·기준 시점: 메인이 지정

## 먼저 읽을 입력

- 과제 원문·관련 요구 ID와 실제 경로:
- 기준 명세·계획·작업 목록의 관련 절:
- 실제 담당자 답변과 관련 코드:
- 입력 고정 방법: 커밋과 clean 상태 또는 실제 관련 파일의 스냅샷·내용 해시

커밋 SHA만으로 미커밋 파일까지 고정됐다고 보지 않는다. 입력이 달라졌으면 영향받는 판단을 재검토 대상으로 보고한다. 메인 대화를 알고 있다고 가정하지 않는다.

## 담당 작업과 수정 경계

- 작업 종류: 원문 검토 / 코드 추적 / 독립 구현 / 기능 검증 중 지정
- UI 적용 단계(관련될 때): first-ui / polish. polish이면 필수 기능·주요 검사 완료 근거와 시간 여유를 메인이 지정
- 수행할 구체 작업:
- 수정 가능한 정확한 파일 또는 비중첩 디렉터리:
- 수정 금지: 기준 명세·계획·작업 목록·배정표·공유 계약·설정 및 다른 담당 파일
- 선행 작업·입출력·오류 처리 계약과 실제 위치:
- 실행 가능한 검사와 공유 데이터에 미치는 영향:
- 완료 조건과 증거:
- 필요 시 시간 예산:

구현·수정 작업은 이 Skill의 `references/ponytail.md`를 읽고 Ponytail full 원칙을 적용한다. 기존 코드와 설치된 의존성을 우선 재사용하되 필수 완료 기준·검증·오류 처리와 설명 기록을 생략하지 않는다. 단순화나 공통 원인 수정이 필요해도 배정 범위를 확대하지 않는다.

UI는 `references/ui-design.md`의 적용 시점을 따른다. frontend-design은 확정 명세의 기본 화면 구현에만, Emil·animate는 기능과 주요 검증 이후 선택 개선에만 쓴다. 후순위 디자인을 이유로 인수 조건이나 원래 작업을 바꾸지 않는다.

모든 필수 입력과 소유권이 정해지면 메인이 배정 준비를 ready로 바꾸고 요청을 고정한다. 실행 상태는 `.cofa/coordination.md` 한 곳에서만 관리한다. ready 요청도 배정표에서 이미 running·accepted 등일 수 있으므로 새 작업으로 재실행하지 않는다. 재개는 같은 담당 세션임이 확인될 때만 가능하며, 담당자가 바뀌면 기존 쓰기 중단을 확인한 뒤 메인이 새 회차를 배정한다.

메인 세션은 계속 독립 작업을 수행한다. 범위 밖 수정이 필요하면 직접 바꾸지 말고 결과에 이유와 영향만 남긴다. 다른 작업자를 생성하거나 배정을 확장하지 않는다.

## 반환 위치

- 이 회차 전용 최종 보고서 경로: 메인이 지정
- 필요 시 검사 로그·도식 등 추가 산출물의 허용 경로:

요청과 배정표는 수정하지 않는다. 보고서는 `.cofa/templates/report.md`를 기준으로 변경 파일·근거·검사·미검증 항목을 담는다. 최종 보고서를 작성하는 동안 완료로 알리지 않고, 작성이 끝나면 작업 ID·회차·결과 경로·완료 또는 차단 상태를 응답하고 종료한다. 기존 회차의 최종 보고서는 덮어쓰지 않는다.
